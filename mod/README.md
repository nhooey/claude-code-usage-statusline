# mod

The TypeScript side of the [redesign](../agents/plans/redesign.md): the
Claude accounting, the usage-source reader and the cells, ported from
`coding_agent_usage_line/` module by module, each under the same name, and
the Claude Code mod, `usage-band`, that draws them.

Node 23.6 or later runs the sources directly, with no build, so the code
keeps to TypeScript's erasable syntax: no `enum`, no `namespace`, no
parameter properties, and imports name their `.ts` files. The tests need no
packages; type checking needs the two dev dependencies, TypeScript and
Node's type definitions.

    cd mod && node --test 'test/*.test.ts'
    cd mod && npm ci && npm run typecheck

`src/spec.ts` is generated by `tools/gen-spec.py` from
`spec/layout.jsonc`; never edit it. Each module's tests compare it with
the Python it ports, through JSON fixtures the Python side writes under
`tests/fixtures/`.

## The mod

This folder is the mod. `.claude-plugin/plugin.json` names it `usage-band`,
`hooks/register.tsx` is its hooks module, and `types/index.d.ts` its
`$.state` contract. It draws four places, and writes one:

- **The band,** above the prompt: the grid's rows
  for the session, from the last status figures document, redrawn as the
  session starts, after each tool call, as a turn starts and ends, every
  5 seconds while a turn runs (never more often than three times as long
  as the last read took) and every 30 seconds otherwise. Its clocks (🔧 ⌛
  ⛳ 🕐 🔜) move each second between reads. While a turn runs its 🎤 and
  🎮 rows are that turn's, live.
- **The footer** under the prompt, `-- INSERT -- ⏵⏵ auto mode on …`: the
  💳 account details at its right end, dim, after Claude Code's own line,
  whose pills stay live.
- **The closing line,** `✻ Worked for 1m 5s`, as the receipt: as a turn
  ends, the band's 🎤 and 🎮 rows stamped there, frozen, and under them
  the turn's 🔺🔖 tag and when it was stamped, so every turn's receipt
  stays in the transcript to scroll back to. 📁 draws the project's root
  as 📦 under its parent, so `📁~/git/📦/mod` is the project's `mod/`
  folder. While a turn runs, 🤖's answering or waiting time is in 🛫's
  column, and its reply ends where 🎤's model starts.
- **The start tag,** under a prompt typed at the composer, at no indent:
  🔻🔖, the turn's tag and when it started, dim.

The hooks import the ports from `src/`. The mod's runtime has no Node and
loads nothing from outside the plugin's folder, so the ports that read
files keep their reads in `src/*_node.ts`, which only Node imports, and
`hooks/edges.ts` makes the same reads through the engine's `$`.

### Configuration

`hooks/config.ts` holds it, in one place: the usage source
(`claude-usage-tracker` by default, as `--usage-source` names it), the
account and period, the `--hide` paths (here `*.plan.five_hour`, 🔋 in
every row, and `*.context.share`, 🧠's ٪ of the window, which only the
mod draws apart from 🧠's size), `--mark-spacing` and
`--subscript-decimals`, the ticks (idle, running, and the clocks'), how many start lines are kept, how long
the receipt waits for its turn, and the version the mod's caches are
keyed by. Set them to what your status line runs with, so the two read
one reading and draw one grid. Edit it, then `/reload-plugins`.

The state directory and the projects directory are the status line's:
`CODING_AGENT_USAGE_LINE_STATE_DIR` (else
`$XDG_STATE_HOME/coding-agent-usage-line`, else
`~/.local/state/coding-agent-usage-line`) and `$CLAUDE_CONFIG_DIR/projects`
(else `~/.claude/projects`). The tracker override,
`CODING_AGENT_USAGE_LINE_CLAUDE_TRACKER_PLIST`, is read as the status line
reads it.

### The receipt

As a turn ends the mod stamps its receipt as the turn's closing line, in
place of Claude Code's `✻ <word> for <duration>`: the rows the band drew
live, frozen and dim, in their colours:

```

🎤 Why is the build slow?                 💰 0.2   🧠 +34k  +3٪  🧩 ▴ 28k ▾7.1k  …
🤖 It's the cold cache on CI.                      🧠 150k        🧩 ▴ 31M ▾997k  …
🎮 📦app 🌿main                            💰 115                 🧩 ▴2.7M ▾841k  …
🔺🔖 8f37748e #12  📅 2026-10-19  🕐 13:06:02

```

A blank row, 🎤, 🤖 and 🎮 laid out at the width the band last drew at,
at no indent as the band's rows are, so each column is under the band's;
then the turn's tag line, drawn as the start tag is, so its 🔺🔖 is under
the 🔻🔖; then a blank row. Until the stamp lands the closing line is a
blank row, and the band keeps the turn's rows until a second after it
lands (`receiptHoldMs`), so neither place is ever without them; then the
band draws none. `sticky` in `hooks/config.ts` (`--sticky` to
`tools/draw-figures.ts`) names the rows, any of `turn`, `agent` and
`session`, that stay on the band once the turn ends; the receipt stamps
the rest. None are sticky by default, so the receipt has all three.
`bandPlace` draws the band under the footer line (`hint`, the default)
or above the prompt (`above`). A
`$.ui.log` line was tried first:
Claude Code draws each as its own notice, `⏺ usage-band:` before it and a
blank row after, in plain dim text.

Claude Code writes a turn's records to the transcript only after its Stop
hooks have run, after the mod hears `turn.complete`, so the stamp waits
for them: it reads the transcript every half second until the newest
prompt's turn is billed and two reads agree on it, for up to 30 seconds,
and goes on after the handler has returned. Then it builds the cost
document as the band builds its status document, with the 📦 🌿 of the
band's last one, times the turn by the engine's duration, and logs it.

Each turn is stamped once: its key, by session, is kept in the mod's
store, so a second `turn.complete` over it logs nothing. A turn whose
records never land, and any failure, logs nothing to the transcript and
says why in the mod's log (below).

The Python's `--mode cost` Stop hook drew a right-aligned receipt of its
own; with the mod loaded, leave it out of `hooks.Stop`, or each turn gets
both.

### Running it

For every session, installed from this repository's marketplace
(`.claude-plugin/marketplace.json` at its root):

    claude plugin marketplace add "$PWD"
    claude plugin install usage-band@claude-code-usage-statusline

or from GitHub, in a session:

    /plugin install usage-band --marketplace nhooey/claude-code-usage-statusline

Installed from a local marketplace, the mod is read from `mod/` itself: a
change here takes effect at the next session start or `/reload-plugins`,
with nothing to update. Installed from GitHub, it is a copy, and
`claude plugin update` brings it up to date.

The mod replaces the status line and the Stop hook's receipt: leave
`statusLine` and the `--mode cost` Stop hook out of `settings.json`. The
agent panel, `subagentStatusLine` with `--mode subagent`, stays.

For one session, with nothing installed and no settings changed:

    claude --plugin-dir "$PWD/mod"

To try it in a session already running, as a dev mod: copy the folder into
the session's mods folder, which the `plugin-authoring` skill makes and
names (`~/.claude/dev-mods/<session id>/`), then reload. A copy and not a
symbolic link: the loader refuses a module that resolves outside the
folder it loads.

    rsync -a --delete --exclude node_modules --exclude test \
      --exclude tools mod/ ~/.claude/dev-mods/<session id>/usage-band/

and in the session, `/reload-plugins`. To remove it, delete that folder
and `/reload-plugins` again.

`--plugin-dir` holds for the one process it is given to: a session
resumed with `claude --resume <id>` alone runs without the mod, and draws
neither the band, the start line nor the receipt. Resume with both:

    claude --plugin-dir "$PWD/mod" --resume <id>

### Its log

The mod's handlers catch what fails, so a failed read leaves the last
drawing up instead of failing Claude Code's event; what they catch is
logged, with what was thrown and where. Each line names its time and the
first eight characters of its session's id, and goes two ways:

- `usage-band.log` in the state directory
  (`~/.local/state/coding-agent-usage-line/usage-band.log` by default),
  always: the newest 500 lines from every session.
- Claude Code's debug log, as `[usage-band] $.ui.log (to debug):` lines,
  when Claude Code runs with `--debug-file <path>` (or `--debug`), beside
  the engine's own lines about the mod's hooks: when each settled, and
  each `$` call that failed.

Each load of the mod writes one line when its first event comes,
`started by session.start in <cwd>`: a session whose turns drew nothing
and that has no such line never loaded the mod. A status read that failed
says why (`refresh: no status document: …`), as does a turn that got no
receipt (`no receipt: …`). The mod times each read, step by step, and a
read over two seconds is logged and shown as a toast, at most one a
minute, with each step's length in ms: `slow read: <ms> (records,
shell, pieces, decode, parse, agents, sum, turns, usage, calib, git)`,
each followed by its figure; `pieces` counts the shell reads.

In the debug log, `classic.SessionStart bypassed by cc-plugin-sec-default`
is expected: Claude Code's security plugin passes the classic events by a
mod a user loads, so the mod finds the transcript by the session's id.

### Its tests

`mod-tests/` runs in Claude Code's own test runner, which loads the mod as
a session would and stands in for the engine beneath it:

    cd mod && npm run test:plugin

It validates the mod and runs the harness tests from a scratch copy, since
the runner collects every `*.test.ts` under the folder it is given and
`test/` holds Node's. Each test answers `$.fs` from the fixture
transcripts (`mod-tests/fixtures.gen.ts`, written by
`node tools/gen-mod-fixtures.ts`; `test/mod-fixtures.test.ts` fails when it
is stale) and checks what the mod drew, the receipt's closing line among
them, against the `src/` functions over the same bytes. It needs the
`claude` command, which CI does not have.

The hooks type-check against the engine's types, which it writes into
`.claude-plugin/types/` the first time it loads the mod (with
`--plugin-dir`, or as a dev mod); they are not committed.

    cd mod && npm run typecheck:plugin
